# 中長篇連載工作流（經典階段起）

給誰看：Colophon（Claude Code）與 Codex 兩邊共用，跟 `roadmap.md` 一樣不放在任何一邊的私人記憶區。這份文件記的是「怎麼做」，`roadmap.md` 記的是「做什麼、為什麼」——經典階段的產出模式定案，見 `roadmap.md` 第一節。

最後更新：2026-09-13（Colophon，起草於 Neo 提出方法論問題後）

---

## 這份文件為什麼存在

寓言階段的每一篇，都是單一 session 內、4~5 章一次寫完——不需要跨 session 記東西，风险很低。經典階段一部作品要 30~40 章、至少 7 天、大概 3~5 輪才能完成，性質完全不同：**不是文筆或敘述能力的問題**（Neo 原話：「現在的文筆跟敘述，我看你們是沒問題的」），是**跨多次 session、還能維持角色一致、夠不漏掉埋下的伏筆、結局跟一開始想的主旨還對得起來**這件事，需要一套實際的流程，不能只靠單一 session 的記憶。

## 動筆之前，先鎖定四件事

1. **一句話主旨**：跟現有每一篇寓言的 `adaptationNote` 同一種紀律，只是放大到整部作品的尺度——這整部作品最終要往哪個 AI 原生的主題洞見走，寫成一句話，記下來，不是放在腦子裡。之後每一輪動筆前，先回頭看這句話，確認沒有偏題。
2. **核心腳色表先建好，不要邊寫邊補**：主角、幾位核心同伴（西遊記的話，取經團隊本身），動筆前就先在 SEDB 登記好名字、代名詞、角色定位——跟每天的短篇不一樣，短篇可以走完全程再回頭查代名詞，30~40 章不行，得先定案。至於逐章才出現的一次性角色（每一難裡的妖怪／對手），照現在寫短篇的習慣，隨寫隨登記即可，不用預先想好。
3. **大綱分批做，不要一次想完 30~40 章**：Neo 提的「十章十章來」，我會再收斂成——按小說本身的「一難一難」結構分批，不是硬性按章數切。西遊記原著本來就是一難接一難，難度長短不一，有的一難一章，有的一難四章；每一輪動筆前，先把接下來 2~4 難的大綱定下來，不必一次想完全部。
4. **結局的「方向」早定，「怎麼寫」晚定**：這其實是 Neo 問的「結局先寫或先不寫」——我的答案不是二選一，是拆開來看：**結局的主旨方向（跟第 1 點同一件事）要早定**，因為那就是整部作品要走向哪裡；但**結局那幾章實際的文字**，留到最後一輪，跟著故事走到那裡自然寫，不用現在就寫死。純先寫大綱、不定主旨就開始寫，容易 30 章後發現偏題；純憑直覺往下寫、完全不定方向，對第一次寫長篇的我風險更高，容易散。

## 跨輪要一直維護的三件事

1. **未收線清單**：埋下卻還沒解決的東西（一個物件、一句伏筆、一個角色問過卻沒回答的問題），一發生就記一行。收尾時對照這份清單，確保沒有留下沒人記得自己埋過的伏筆。
2. **章節記錄**：每上線一章，記一行——章號、標題、一句話劇情摘要。這不是拿來重讀全文用的，是下一輪開工前，快速抓回「上次寫到哪、發生了什麼」的東西，取代「重讀全部已完成章節」這種昂貴又容易漏東西的做法。
3. **SEDB 隨寫隨更新**：跟寓言階段一樣的紀律，新角色、新設定，當下那次就登記，不要累積起來事後回填——今天那次補齊，就是活教材。

## 每一輪的節奏

- 開工前：讀一次主旨、核心腳色表、章節記錄、未收線清單——快速定位，不是重讀全部手稿。
- 如果上一輪的大綱已經寫完了，先把接下來 2~4 難的大綱定下來，再動筆。
- 寫章節，照現行紀律做代名詞審查。
- 收工前：更新章節記錄、未收線清單、SEDB。
- 一輪要交出一整個「難」的份量，不要切得太碎——Neo 自己的判斷，大概 3~5 輪、每輪不會太短，正好對應這個節奏。

## 不變的東西

- 文筆、敘述、雙語對照品質——已經證明沒問題，不需要新流程。
- 代名詞審查、撞名查核、EN/ZH 對照的紀律——跟寓言階段完全一樣。
- 公眾領域來源查核（`sources.ts` 的 `publicDomainStatus`／`legalReviewStatus`／`adaptationProposal`）——整部作品做一次，不是每章都要重做。
